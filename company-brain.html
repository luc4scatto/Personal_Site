Internal project

Company Brain

Information about a product lives in many systems: technical data, commercial texts and attributes, official photos, technical drawings and standard components, prototype tracking, plus design manuals and internal notes. Each has its own interface, its own login, its own way of searching, so a simple question like "what material is this model, and how is it built?" often means opening three or four programs and knowing exactly where to look.

Company Brain is one chat that fixes that. You ask in plain language, like you would ask an expert colleague, and it reads the answer live from the company systems and gives it back with photos, drawings and charts. It runs on our own servers, so nothing leaves the company, and every answer says which system each piece of data came from.

How it works

One question goes through a chat, a language model that decides what to do, and small purpose-built tools that each know how to talk to one system.

  1. Chat Internal web chat, questions in plain language
  2. Language model Runs on our own server on a dedicated GPU, understands the question and picks a tool
  3. Tools Small custom programs, one per source: fetch, calculate, prepare the result
  4. Company systems Technical data, catalog, photos, drawings, prototypes, manuals

From question to answer

  1. Ask The user writes a question.
  2. Understand The language model works out what is needed.
  3. Call a tool It calls the right tool, a program that knows how to query one system.
  4. Retrieve The tool fetches the data, does the math and prepares the result.
  5. Present The model presents it in a readable form, with its sources.

Design choices

Everything in-house

The model runs on an internal server with a dedicated GPU. No question and no data is ever sent to an external service.

Read-only

It consults the company systems but cannot change them: every connection uses a read-only account.

The code does the math

Language models are good with words and less reliable with numbers, so averages, counts, comparisons and charts are computed exactly by the tools. The model only receives the result to explain.

No copies of the data

Photos, drawings and documents are read from the original source at the moment of the question, never duplicated on the server, so what you see is always current.

It asks instead of guessing

When a question is ambiguous (which season? which colorway? which component type?) it shows choice buttons right in the chat.

Controlled access

Only authenticated users can use it, and each group only sees the tools relevant to its own work.

Monitoring

An internal dashboard shows whether every service is up, how loaded the server is and how fast the model answers, how many questions are asked and which tools get used the most. It tells us whether the system is healthy and where to invest next.

Looking back

What I learned

Small and well taught beats big and alone

The real work is in the tools: giving the model data that is already clean, ordered and short.

Less text is better

Long answers confuse the model and eat memory, so every tool returns only what is needed.

Charts need a point

A chart earns its place when it shows a trend or a comparison, not fifty nearly equal values.

Asking beats guessing

The choice buttons removed a lot of wrong answers.

Limits and next steps

One GPU

With many users at once, answers slow down.

Bigger models need more hardware

More capable models would need a more powerful machine, which is the next step, along with more data sources and other departments.

Finds and summarizes

It is good at finding and summarizing. Decisions stay with people.
